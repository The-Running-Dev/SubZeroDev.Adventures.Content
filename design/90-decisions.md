### 2026-08-12 — Pin `engine/` to squash-merge commits on `main`, never to feature-branch tips

Context: `engine/` was pinned to `4d48583`, the pre-squash tip of GameEngine's W74 authoring-seam
branch. GitHub squash-merged that branch as `eabb620` (#299) and deleted the branch, leaving
`4d48583` reachable from no ref — `git merge-base --is-ancestor 4d48583 origin/main` fails and
`git branch -r --contains` returns nothing. It still resolves because GitHub retains the loose
object, but it would not survive a shallow clone or an upstream GC, and CI would fail at
`git submodule update` with no indication of why.
Chosen: repoint `engine/` to `eabb620`. The pointer only ever names a commit reachable from
GameEngine's `main`; where a pull request is squash-merged, that is the squash commit, not the
branch tip that produced it. `4d48583..eabb620` touches only `src/engine/src/authoring.ts`
(re-exports routed through `./index.js`, exported names unchanged) and `scripts/export-campaigns.ts`,
so the surface this repository imports is unaffected.
Rejected: leaving the pointer (works today, fails on the first clean or shallow clone, with a
failure mode that reads as a network error); pinning to a tag instead (GameEngine tags releases,
not every merge, so the pointer would lag content this repository needs); vendoring the built
package (contracts/ already carries a vendored tgz for its own reasons — a second copy of the
engine here would reintroduce the two-sources-of-truth problem the entry below rejects).
Reversibility: cheap — a one-line submodule pointer revert.

### 2026-08-12 — TypeScript source and Engine `/authoring` are the content publication seam

Context: this repository previously copied JSON generated by the Engine submodule. That made
the published artifacts canonical by accident and prevented content-specific validation from
running where content is owned.
Chosen: this repository owns TypeScript campaign sources and an ordered catalog exporter. It
uses GameEngine's public runtime API and `/authoring` subpath only. JSON is deterministically
generated with `JSON.stringify(value, null, 2)` and is checked for drift. TypeScript, tsx,
Vitest, Prettier, and oxlint are development dependencies because the repository now compiles,
executes, tests, and formats authored source.
Rejected: retaining copy-from-Engine export (two sources of truth); authoring raw JSON only
(loses typed builders and migration coverage); deep Engine imports (would couple content to
private paths); a custom compiler (more maintenance than TypeScript's existing ecosystem).
Reversibility: moderate — source ownership is deliberate, while generated JSON can always be
regenerated from the catalog.

### 2026-08-12 — AGENTS.md/CLAUDE.md direction and design/ placement, on first kit install

Context: neither AGENTS.md nor CLAUDE.md existed yet, so INSTALL.md's "neither exists" case applied — the kit's AGENTS.md needed a project-identity section, sourced from README.md rather than invented, and design/ needed a placement check.
Chosen: kit's AGENTS.md holds the contract plus a project-identity section (this repo publishes campaign JSON that SubZeroDev.Adventures fetches at runtime, via the engine/ and contracts/ submodules); CLAUDE.md is the pointer. design/ installed at the repository root — no docs/, plans/, adr/, rfc/, or decisions/ directory existed to compete with it.
Rejected: inverting the AGENTS.md/CLAUDE.md direction (no reason to — nothing existed yet to prefer either arrangement); relocating design/ (nothing occupied the path).
Reversibility: cheap — both are uncommitted at time of writing, and the direction/placement can still be changed before the first commit.
